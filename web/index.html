由发送方关闭；关闭后可以继续读完缓冲值。
为什么这和 Java 的队列不完全一样？

有缓冲 Channel 可以类比有界 BlockingQueue，但容量为 0 时，发送与接收必须配对；它更接近一次交接。Channel 也有关闭语义：缓冲读完后返回零值与 ok=false。这个实验每侧只模拟一个 goroutine，一侧阻塞后不能继续执行下一次操作。

动画与本仓库的实现有什么对应关系？

这里演示流式路径：A 返回可切换的错误（例如 503）时直接尝试 B，不在 A 上重试。400 是不可重试错误。进入流读取后产生的读错误会原样返回，不再 fallback；客户端取消会结束请求。非流式路径才会按 ATTEMPTS 在同一上游重试。本动画的“断流”特指读取返回错误，并不等同于所有提前 EOF 场景。
